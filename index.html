Title

Your knowledge base, checked like code.

Aim

Specs, decisions and records live in a git knowledge base that people and agents both edit. The Cube checks every file, draws what depends on what, and its git hooks refuse a commit that adds an error, whoever wrote it.

  1. Install

    $curl -fsSL https://cube.happonomy.org/install.sh | sh
    PS>irm https://cube.happonomy.org/install.ps1 | iex

    The installer checks the signature, GitHub's release record and the SHA-256 before it installs anything. See page 5.

  2. Start from the starter kit

    Extract it into a git repository, then run cube adopt and cube check. Quick start

No. 002
Title

A commit that adds an error does not get in.

Record

shared/conventions/module_spec.yml, the Conventions module of the starter kit, continued from page 1.

Entry
17conventions_ref: ""
18design_system_ref: "shared/design-system/"
18design_system_ref: "shared/design_system/"
19architecture_ref: "shared/architecture/"

Refused: 0 to 1 ERROR (baseline 0). The folder is design_system.Witnessed: 0 ERROR (baseline 0). Commit allowed.

The hooks compare a commit with its parent. More errors than before: refused. The same or fewer: allowed. The errors an existing base already has do not block you; a new one does.

A commit cannot quietly weaken a kit's own rules. Switching a check off, deleting the evidence a check reads or editing its test is itself an error (SHORTCUT_*), and loosening a rule needs a rule-change act by a person.

These checks guard the knowledge base, not your machine. With the alpha's per-user install, an agent that runs as your account could still replace the cube program or change your git settings; the hooks warn you about that, and an install owned by root comes in a later release.

Title

Every reference is a checked link.

Note

Each spec, decision and record is a typed node: a module spec, its overview, its changelog, a decision log. Its *_ref fields and links are edges. The Cube draws the graph and checks that every edge lands on something that exists, so you can see what depends on what before you change it.

No. 005
Title

Install it, and check what you installed.

Method
$curl -fsSL https://cube.happonomy.org/install.sh | sh
PS>irm https://cube.happonomy.org/install.ps1 | iex

For your account only, no administrator rights: ~/.local/bin on Linux and macOS, %LOCALAPPDATA% on Windows. Read the scripts before you run them: install.sh, install.ps1.

  1. The signed manifest

    The list of releases is signed with minisign. The installer checks the signature when minisign is installed.

    Check it by hand
    minisign -Vm alpha.json -P CUBE-PUBKEY-PENDING

  2. GitHub's release record

    The archive's digest on GitHub equals the manifest's, and the release is immutable: its files and its tag cannot change after publication.

  3. The SHA-256 of the download

    The file on your disk is the file the manifest names. On a mismatch nothing is installed.

Note
The checks stop a swapped archive or manifest. The script runs them, so read it first if you want to: how.

No. 006
Title

What this alpha does not do yet.

Limits
  • macOS and Windowscube check runs the engine's own checks and skips the kit's checks with a warning (KIT_CHECKS_SKIPPED): the check that a program is safe to run exists only for Linux so far. The git hooks (and cube setup) refuse there until a later release adds the macOS and Windows forms. The other commands work.
  • Per-user installThe installer puts cube in your home folder. The git hooks run a program your account owns only after you opt it in (cube setup prints the git config --global --add cube.allowUserOwned command), and then every hook warns that it is not tamper-proof: an agent that runs as your account could replace the program or change your git settings. An install owned by root, which closes this gap, comes in a later release.
  • No self updateThere is no cube self update and no update check yet. To update, run the installer again.
  • Signaturescube itself does not check signatures yet. The installer checks the manifest's minisign signature only when the minisign program is installed. It always checks GitHub's record of the release (immutable, and the same SHA-256 digest as the manifest), which is a second, independent source, and the SHA-256 of the download. The release that brings cube self update checks signatures in cube itself.
  • Kits and packs are plain archives, not yet signed bundles with an index.
  • No code signingThe programs are not code-signed in the alpha and beta. Windows Smart App Control can block them. On macOS, a copy downloaded with a web browser is quarantined; the installer downloads with curl, which does not quarantine it, so use the install command.
  • Agentscube and its git hooks work with any agent that runs shell commands. The kits' agent guidance (skills, helper agents, slash commands) uses Claude Code's .claude/ layout for now; other agents get the checks and the hooks but may not load that guidance on their own.
  • The kit's checks need Python 3 with PyYAML.
  • Not yet: cube setup mergiraf, the AGENTS.md target of cube skill render, and acknowledging agent acts in cube inbox.
