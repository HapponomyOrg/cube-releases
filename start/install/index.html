Install and verify

No. 008

The Cube is one program, cube, plus two tool programs that it runs from its own folder: cube-index (the index) and cube-graph (the knowledge graph). The installer puts all three on your machine for your own account. What your machine needs is on requirements.

Where it installs

Section titled “Where it installs”

The installer installs for your own account only. Do not run it with sudo: it refuses to run through sudo.

System Folder
Linux and macOS ~/.local/bin
Windows %LOCALAPPDATA%\Programs\cube, added to your user PATH

Set these environment variables before you run the installer to change what it does:

Variable What it does
CUBE_INSTALL_DIR Another folder for the programs (an absolute path).
CUBE_CHANNEL The channel: alpha, the default. beta and stable come later.
CUBE_INSTALL_SKIP_GITHUB_CHECK=1 Skip the check against GitHub’s record (see below). Use it only when GitHub’s API cannot be reached.

To update, run the installer again.

What the installer checks

Section titled “What the installer checks”

The installer installs nothing unless every check passes:

  1. The signature. The channel manifest, https://happonomyorg.github.io/cube-releases/alpha.json, names the newest version and the SHA-256 of every download. If the minisign program is installed, the manifest’s signature (alpha.json.minisig) must match one of Happonomy’s two public keys. Without minisign, this check is skipped, and the installer says so.
  2. GitHub’s record. GitHub’s API must mark the release immutable (its files can never change), and GitHub’s SHA-256 digest of the download must equal the manifest’s. This is a second source, independent of this site.
  3. The download. The SHA-256 of the downloaded archive must equal the manifest’s.

The installer also refuses a manifest that has expired, and a cube that does not report the manifest’s version. Each manifest is valid for 90 days, and it is signed again every month. On any failure, the installer stops with an error, removes what it downloaded and leaves no new program.

These checks stop a swapped archive or manifest: someone who changes the files on this site cannot make the installer accept a different program, as long as GitHub’s check runs. They cannot protect you from a changed install script, because the script is what runs the checks.

Check the script first

Section titled “Check the script first”

Each release also carries both install scripts as release assets on GitHub, where they cannot change after publication, and GitHub records the SHA-256 of each. To check a script before you run it, download it, compare it with that record or read it, then run the saved copy. With the GitHub CLI, gh release verify-asset does the comparison (use the newest release, for example cube-v0.1.0); without it, compare the output of sha256sum with the digest GitHub shows for the asset on the release page.

When GitHub’s API cannot be reached

Section titled “When GitHub’s API cannot be reached”

GitHub allows 60 anonymous API calls an hour from one address. If the API cannot be reached (you are offline, behind a proxy, or over that limit), the installer stops and names the opt-out. To install anyway, set CUBE_INSTALL_SKIP_GITHUB_CHECK=1. The installer then warns that GitHub’s record is not checked: only this site’s manifest vouches for the file.

What a download holds

Section titled “What a download holds”

Each program archive holds cube, cube-index and cube-graph (.exe on Windows), LICENSE, THIRD-PARTY-NOTICES.md and README.md. Each file of a release has a .sha256 file beside it on the releases page.
